## 1. Overview & Architecture

HoneyVault is composed of three runtime components and two dedicated databases:

```text
       ┌────────────────────────┐
       │     Frontend (Vercel)  │
       │  React + Vite SPA      │
       └───────────┬────────────┘
                   │ HTTPS (API requests)
                   ▼
       ┌────────────────────────┐         Signed / mTLS          ┌────────────────────────┐
       │   HoneyVault API       │ ─────────────────────────────> │      Honeychecker      │
       │   (Render / Docker)    │                                │   (Render / Docker)    │
       └───────────┬────────────┘                                └───────────┬────────────┘
                   │                                                         │
                   │ SQL (psycopg 3)                                         │ SQL (psycopg 3)
                   ▼                                                         ▼
       ┌────────────────────────┐                                ┌────────────────────────┐
       │    Neon Database 1     │                                │    Neon Database 2     │
       │     `honeyvault`       │                                │    `honeychecker`      │
       └────────────────────────┘                                └────────────────────────┘
```

> [!IMPORTANT]
> **Database Isolation Invariant:** The `honeyvault` and `honeychecker` databases are strictly isolated. The API never has database access or credentials to the honeychecker database, ensuring that an SQL injection or compromised API DB snapshot does not disclose which candidate sweetword is the user's authentic password.

## 3. Local Docker Usage

Docker Compose orchestrates the full four-tier stack locally (Postgres, Honeychecker, API, and Frontend).

### 3.1 Services Defined in `docker-compose.yml`
- **`db`**: PostgreSQL 16 Alpine container. Runs `docker/postgres-init.sql` on first initialization to create separate `honeyvault` and `honeychecker` roles and databases with proper privileges.
- **`honeychecker`**: Honeychecker service running Python 3.12, exposed on port `8001`.
- **`api`**: HoneyVault API running Python 3.12, exposed on port `8000`. Runs `alembic upgrade head` and conditional demo seeding on container boot.
- **`frontend`**: React + Vite SPA built via Node 22 Alpine and served via Nginx on port `8080`, mapped locally to port `5173`. Includes SPA route fallback to `/index.html`.

### 3.2 Quickstart Commands

```bash
# 1. Build all container images (build context is repo root)
docker compose build

# 2. Start stack in background
docker compose up -d

# 3. Verify health status
curl http://localhost:8000/api/health
curl http://localhost:8001/hc/health
curl http://localhost:5173/healthz

# 4. View container logs
docker compose logs -f api
docker compose logs -f frontend
docker compose logs -f honeychecker

# 5. Stop services (preserves database volume)
docker compose down

# 6. Stop and wipe database volume (clean reset)
docker compose down -v
```

### 3.3 Health Check Verification
When healthy, the endpoints return:
- `http://localhost:8000/api/health`:
  ```json
  {"status":"ok","version":"0.1.0","honeycore_impl":"stub","honeychecker":"ok"}
  ```
- `http://localhost:8001/hc/health`:
  ```json
  {"status":"ok","service":"honeychecker","version":"0.1.0","db":"ok"}
  ```
- `http://localhost:5173/`: Returns HTTP 200 with the HoneyVault SPA HTML shell.

## 4. Phase 2: Parth's mTLS Transport Profile

In Phase 2, internal service-to-service communication between `honeyvault-api` and `honeychecker` can operate over mutual TLS (`mTLS`) using local certificates generated by `pki/`.

### 4.1 Architecture & Flow
- **Issuing CA** issues:
  - Server certificate for Honeychecker: SAN `localhost`, `honeychecker`, CN `honeychecker-server`.
  - Client certificate for API: EKU `clientAuth`, CN `honeyvault-api`.
- **Uvicorn execution** in `honeychecker`:
  ```bash
  uvicorn app.main:app --host 0.0.0.0 --port 8001 \
    --ssl-certfile /app/pki/honeychecker-server.crt \
    --ssl-keyfile /app/pki/honeychecker-server.key \
    --ssl-ca-certs /app/pki/root-ca.crt \
    --ssl-cert-reqs 2
  ```
- **Httpx execution** in `honeyvault-api`:
  ```python
  client = httpx.Client(
      cert=("/app/pki/api-client.crt", "/app/pki/api-client.key"),
      verify="/app/pki/root-ca.crt",
  )
  ```
- **Compose Profile**:
  The commented `api-mtls` and `honeychecker-mtls` configurations in `docker-compose.yml` activate under `docker compose --profile mtls up`.

## 5. Staging Runbook (Step-by-Step Deployment)

Follow this precise sequence to deploy HoneyVault from scratch to staging:

```text
Step 1: Neon Databases ──> Step 2: Render Blueprint ──> Step 3: Vercel Frontend ──> Step 4: CORS Setup ──> Step 5: Smoke Test
```

### Step 1: Neon Postgres Provisioning
1. Log in to [Neon Console](https://console.neon.tech).
2. Create project `honeyvault-staging` in region **AWS Singapore (`ap-southeast-1`)**.
3. Under this project, create two databases:
   - `honeyvault` (for HoneyVault API)
   - `honeychecker` (for Honeychecker)
4. Record both connection strings with `postgresql+psycopg://` and `sslmode=require`.

### Step 2: Render Blueprint Deployment
1. Log in to [Render Dashboard](https://dashboard.render.com).
2. Go to **Blueprints** → **New Blueprint Instance**.
3. Select repository `rohansd05/CNS---Honey-Encryption-Vault` and branch `dev`.
4. Render loads `render.yaml` and initializes:
   - `honeyvault-api` (Docker web service, region `singapore`)
   - `honeyvault-honeychecker` (Docker web service, region `singapore`)
5. In the Render Dashboard, supply the missing secret env vars (`sync: false`):
   - `DATABASE_URL`: Neon `honeyvault` connection string.
   - `HC_DATABASE_URL`: Neon `honeychecker` connection string.
   - `JWT_SECRET`: Random 48-byte URL-safe string.
   - `KEY_WRAP_SECRET`: Random 32-byte Base64 string.
   - `HONEYCHECKER_URL`: Internal or public Render URL of `honeyvault-honeychecker`.
   - `HC_CLIENT_CERT_B64`, `HC_CLIENT_KEY_B64`, `HC_TRUSTED_CA_CERT_B64`, `HC_ISSUING_CA_CERT_B64`: Base64 PEM certificates from `pki/out`.
6. Trigger initial deployment.

### Step 3: Vercel Frontend Deployment
1. Log in to [Vercel](https://vercel.com).
2. Import repository `rohansd05/CNS---Honey-Encryption-Vault`, branch `dev`.
3. Set **Root Directory** to `frontend`.
4. Configure environment variables:
   - `VITE_API_BASE_URL`: Public Render URL of `honeyvault-api` (e.g. `https://honeyvault-api.onrender.com`).
   - `VITE_USE_MOCKS`: `false`.
   - `VITE_DEMO_MODE`: `true`.
   - `VITE_APP_NAME`: `HoneyVault`.
5. Deploy and note the assigned production domain (e.g. `https://honeyvault-staging.vercel.app`).

### Step 4: CORS Configuration
1. In the Render Dashboard for `honeyvault-api`, update `ALLOWED_ORIGINS`:
   ```text
   ALLOWED_ORIGINS=https://honeyvault-staging.vercel.app,http://localhost:5173
   ```
2. Trigger a redeploy of `honeyvault-api` to apply the updated origin whitelist.

### Step 5: Execute End-to-End Smoke Test
Run the automated smoke test script against the deployed staging endpoints:

```bash
python -m scripts.smoke_test \
  --api https://honeyvault-api.onrender.com \
  --frontend https://honeyvault-staging.vercel.app
```

Verify that all essential checks PASS and unreleased endpoints show SKIP.

## 7. "Warm Up Before Demo" Checklist

Render free-tier instances sleep after 15 minutes of inactivity and Neon databases scale down to zero compute. Cold starts can take 30–60 seconds on initial load.

### Pre-Demo Warmup Protocol (Execute 5–10 minutes before presenting):

1. **Ping Honeychecker Health Endpoint:**
   ```bash
   curl -i https://honeyvault-honeychecker.onrender.com/hc/health
   ```
   *Expected response:* HTTP 200 `{"status":"ok","service":"honeychecker","version":"...","db":"ok"}`

2. **Ping API Health Endpoint:**
   ```bash
   curl -i https://honeyvault-api.onrender.com/api/health
   ```
   *Expected response:* HTTP 200 `{"status":"ok","version":"...","honeycore_impl":"...","honeychecker":"ok"}`  
   *Note:* Ensure `"honeychecker": "ok"` in the response. If `"down"`, wait 10 seconds for the honeychecker container to finish starting.

3. **Ping Frontend Web App:**
   ```bash
   curl -i https://honeyvault.vercel.app/
   ```
   *Expected response:* HTTP 200 (HTML document delivered via Vercel Edge CDN).

4. **Verify Smoke Test Output:**
   ```bash
   python -m scripts.smoke_test --api https://honeyvault-api.onrender.com --frontend https://honeyvault.vercel.app
   ```
