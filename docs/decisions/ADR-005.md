# ADR-005: Honeychecker transport: mTLS locally, signed requests on Render

- Status: Accepted
- Date: 2026-10-03
- Source: PROJECT-BRIEF.md §13

## Context
The API→honeychecker channel must be authenticated, otherwise an attacker could forge `match: true`. Render terminates TLS at its proxy, so end-to-end mutual TLS between two Render services is not possible on the free tier.

## Decision
`HONEYCHECKER_TRANSPORT` / `HC_TRANSPORT` select the mode: `plain` (local dev), `mtls` (docker-compose; uvicorn requires client certs from our CA, CN checked) or `signed` (Render; ECDSA-P256 signature over method, path, timestamp, nonce and body hash, with X-HV-* headers, ±60 s window and a 5-minute nonce replay cache). Both use certificates from our own Issuing CA.

## Consequences
- Real mTLS is demonstrated in compose; production still authenticates every request.
- Signed mode adds code (`honeycore/transport.py`, `honeychecker/app/security.py`) and needs clock sync.
- `plain` must never be used outside local development.
