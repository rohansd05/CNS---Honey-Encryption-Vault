# ADR-006: Wrap identity private keys with a server KEK

- Status: Accepted
- Date: 2026-10-03
- Source: PROJECT-BRIEF.md §13

## Context
Each user has a P-256 identity keypair for sharing. Its private key must be stored server-side. Wrapping it under the master password would add a verifiable AES-GCM ciphertext keyed by the master password — an offline oracle. Wrapping under the login password would let an attacker verify login-password guesses and weaken honeywords.

## Decision
Private keys are wrapped with AES-256-GCM under `KEY_WRAP_SECRET`, a 32-byte server key-encryption key held in environment variables, never in the DB.

## Consequences
- Neither password gets an oracle.
- A full server compromise (DB + env) exposes identity keys — out of scope per the threat model.
- KEK rotation requires re-wrapping all keys (script, future work).
