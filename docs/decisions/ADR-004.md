# ADR-004: Per-entry AES-256-CTR with no MAC; Sigil for typo awareness

- Status: Accepted
- Date: 2026-10-03
- Source: PROJECT-BRIEF.md §13

## Context
Any integrity check on the honey ciphertext (MAC, GCM tag, checksum, padding) recreates the offline oracle. Without one, a mistyped master password silently decrypts to a decoy and, if used to write, stores an entry under the wrong key.

## Decision
Each entry is encrypted independently with AES-256-CTR under `enc_key` and a random 16-byte nonce; no MAC. Add/update re-encrypt only that entry. A Vault Sigil (3 emojis + colour from `HMAC(sigil_key, "sigil")`, never stored) lets users recognise their own key.

## Consequences
- No oracle: every password yields a full, plausible vault.
- A typo while writing damages at most one entry.
- Ciphertext is malleable (no integrity); acceptable because the threat is offline theft, not tampering with the DB.
- Users must learn their Sigil; the UI shows it before writes.
- Entry count is visible from ciphertext count.
