# ADR-001: Store entry service names in plaintext

- Status: Accepted
- Date: 2026-10-03
- Source: PROJECT-BRIEF.md §13

## Context
Each vault entry has a service (e.g. github.com), a username and a password. Encoding the service through the DTE would need a model of which sites people use and how they pair with credentials. The server also needs the service to list, sort and share entries without the master password. NoCrack and LastPass (URLs) leave this metadata unencrypted too.

## Decision
`service` is plaintext metadata in vault blob v1. Only (username, password) go through the Entry DTE and the cipher. Decoy vaults therefore show the same services as the real one.

## Consequences
- Simpler DTE and fixed 532-byte seeds.
- An attacker who steals the DB learns which services a user has, but not the credentials.
- Decoys are consistent with the visible services, so the service list does not help tell real from decoy.
- Documented as a limitation in the threat model.
